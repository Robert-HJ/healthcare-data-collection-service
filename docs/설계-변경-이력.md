# 설계 변경 이력

## 2026-07-25 Refresh Token 구현 제외

초기 설계에서는 로그인 시 Access Token과 Refresh Token을 발급하고, Refresh Token의 회전과 폐기를 위해 MySQL에 저장하는 구조를 계획했다. 구현 범위를 검토한 결과 현재는 Access Token만 발급하는 구조로 변경한다.

현재 요구사항은 이메일과 비밀번호를 이용한 로그인과 인증된 API 호출이며, Access Token만으로도 이를 충족할 수 있다. 반면 Refresh Token을 도입하려면 토큰 발급뿐 아니라 다중 기기 로그인, 재발급 시 회전, 로그아웃과 폐기, 탈취 토큰의 재사용 감지, 동시 재발급 요청과 만료 데이터 정리까지 함께 다뤄야 한다. 이 중 일부만 구현하면 로그인 유지 기능은 제공하더라도 안전한 세션 관리 구조라고 보기 어렵다.

현재 구조에서는 Access Token이 만료되면 사용자가 다시 로그인해야 하며, 발급된 토큰을 서버에서 즉시 폐기할 수 없다. 로그아웃은 클라이언트가 토큰을 제거하는 방식으로 처리한다. 이 제한을 줄이기 위해 Access Token의 만료 시간을 제한적으로 설정한다.

향후 로그인 유지가 필요해지면 단순 로그인 이력이 아니라 현재 유효한 인증 세션을 관리하는 별도 모델을 추가하고, Refresh Token의 회전과 폐기 정책을 함께 구현한다.
